Peak measured output throughput: 243.93 tok/s.
COMPARISON IS NOT CONTROLLED. The g5g baseline (2026-08-14-rust-frontend-g5g, Py-1) ran vLLM 0.27.2rc1.dev0 built from source on g5g.4xlarge (16 vCPU, on-demand) under `vllm bench serve` with --dataset-name random. This ran vLLM 0.28.0 from the published amd64 image on g4dn.xlarge (4 vCPU, spot) under this rig's own harness with English filler sized via /tokenize. Engine version, harness, host size and prompt content all differ. The GPUs do not: both SM 7.5, both 15360 MiB, both 5001 MHz memory clock, and both report GPU KV cache of exactly 329,579 tokens.
Because decode is GPU-bandwidth-bound and the two GPUs are spec-identical, a 42-48% throughput gap CANNOT be attributed to the host CPU -- the CPU is not the bottleneck at these rates. Engine version is the leading candidate. Do not report this as an Intel-vs-Arm result without a matched-version run.
